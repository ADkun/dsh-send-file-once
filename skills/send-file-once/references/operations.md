# 参数决策 · 失败处置 · 安全模型

> 何时读：判断「该设多少天 / 几次 / 要不要口令」或「失败了怎么办」。grep 关键词：决策 失败 限额 安全 矩阵。

## 一、参数决策矩阵
| 场景 | --expires | --views | --passphrase | 说明 |
|---|---|---|---|---|
| 默认（拿不准就给最严） | 1d | 1 | 否 | 一次即焚，最安全 |
| 对方可能过几天才取 | 3d–7d | 1 | 视敏感度 | 期限是「最迟到何时作废」，不是保多久 |
| 同一人手机 + 电脑各下一次 | 1d | 2 | 否 | 每多一次 = 多一份暴露 |
| 发给一个小组（≤10 人） | 1d | 3–10 | 是 | 建议同时加口令，口令另发 |
| 高敏（密钥 / 凭证 / 私钥） | 1h–1d | 1 | 是 | 口令必须另走通道 |
| 大文件（接近但 ≤250MiB） | 1d | 1 | 视情况 | 先确认对方能及时下载 |

原则：**期限取最短够用，次数取最少够用**；放大任何一项都要在交付时明说风险。

## 二、限额与硬约束
- 单文件 ≤ 250 MiB（本技能软上限默认 250MiB，超限直接拒绝）。
- 有效期 1h–30d；次数 1–10；超范围会被 1time 本地校验拒绝。
- 公共实例有速率限制，别短时间连发；失败先 `doctor`。
- 需 Node ≥ 20 且已 `npm install -g @1time/cli`。

## 三、失败处置
| 现象 / 退出码 | 原因 | 处置 |
|---|---|---|
| 4 / 未找到 1time | 未安装或不在 PATH | npm install -g @1time/cli，再 doctor |
| 2 / 文件不存在 | 路径错 | 核对路径（含空格要加引号） |
| 2 / 超过上限 | 文件 >250MiB | 分卷 / 压缩 / 换方案，并告知用户 |
| 2 / 未能解析出链接 | 网络异常或被限流 | 稍后重试，检查网络与限流 |
| 3 / 上传失败 | 网络、限流、服务端拒绝 | 读 stderr 原文；限流则降频；仍失败改期再试 |
| 3 / 读取失败 | 链接过期 / 次数用尽 / 口令错 | 向发送方确认；口令链接须带正确口令 |
| 读回提示 consumed | 该链接已被使用 | 正常「阅后即焚」行为；需重新生成 |

## 四、安全模型（必读）
- 端到端加密：内容在本地加密后才上传，服务器只见密文与读令牌的 SHA-256 哈希，读不到明文。
- **链接的 # 之后就是解密钥匙**；链接本身 = 钥匙，拿到链接 = 拿到内容。
- `--passphrase` / `1TIME_PASSPHRASE` 是第二把锁；**口令必须与链接走不同通道**，否则等于没加。
- 密码 / Token / 密钥等文本优先 `--text`（经 stdin 管道，不落命令行历史）；但文本不支持口令，极敏建议加密成文件再发。
- 不要把链接写进公开群、工单、日志、截图或对话记录。
